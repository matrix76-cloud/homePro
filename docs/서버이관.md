## 0. 시작 전 반드시 확인할 것

### Firestore 리전
타깃 프로젝트의 Firestore 가 **nam5(미국)** 로 생성돼 있다. 기존은 서울(asia-northeast3)이다.

Firestore 리전은 **한 번 정하면 바꿀 수 없다.** 미국으로 두면
- 한국 사용자의 모든 조회가 태평양을 왕복한다
- 서울에 배포된 Functions 가 미국 DB 를 호출하므로, 오더 생성·채팅 트리거마다 지연이 붙는다

타깃 DB 가 아직 비어 있을 때만 고칠 수 있다. Owner 권한으로:

```bash
gcloud firestore databases delete --database='(default)' --project=homepro-9202f
gcloud firestore databases create --database='(default)' --location=asia-northeast3 --project=homepro-9202f
```

데이터를 한 건이라도 넣은 뒤에는 되돌리기 어려우니 **이관 착수 전에 끝내야 한다.**

### 요금제
Cloud Functions 배포에는 **Blaze(종량제) + 결제수단 등록**이 필요하다. 무료(Spark)로는 배포 자체가 안 된다.

### 권한
데이터 이관은 서비스 계정 키로 되지만, **Hosting 배포·규칙 배포에는 사람 계정 권한이 필요하다.**
의뢰인 콘솔에서 작업 계정을 **소유자(Owner)** 로 추가받는 게 가장 확실하다.

## 1. 코드 준비 (완료)

프로젝트 값이 소스에 하드코딩돼 있으면 이관 후에도 옛 계정을 계속 바라본다. 전부 환경변수로 뺐다.

| 파일 | 내용 |
|---|---|
| `src/api/config.js` | Firebase 설정을 `REACT_APP_FB_*` 에서 읽음. `functionUrl()`·`PUBLIC_BASE_URL` 제공 |
| `src/config/homeproConfig.js` | Functions URL 을 `functionUrl()` 로 조립 |
| `src/page/main/MobileMainpage.js` | 초대 공유 링크 도메인을 `PUBLIC_BASE_URL` 로 |
| `src/page/test/SeedLoginPage.js`, `src/dev/reviewAuth.js` | 시드 로그인 함수 URL 조립 |
| `public/index.html` | OG 태그 도메인을 `%REACT_APP_PUBLIC_BASE_URL%` 로 |
| `functions/config.js` | 카카오 키·SMS 게이트웨이를 env 에서만 읽음(하드코딩 폴백 제거) |

환경변수 파일:

| 파일 | 용도 | 커밋 |
|---|---|---|
| `.env` | 로컬 개발 — 현재는 기존 프로젝트를 바라봄 | X |
| `.env.client` | 의뢰인 프로젝트 값. **아직 적용 전** | X |
| `.env.example` | 빈 템플릿 | O |
| `functions/.env.homepro-43f7f` | 기존 프로젝트용 키 | X |
| `functions/.env.homepro-9202f` | 의뢰인 프로젝트용 키 — **값 비어 있음** | X |
| `functions/.env.example` | 빈 템플릿 | O |

`.env.client` 를 일부러 `.env.production` 이라 하지 않았다. 그 이름이면 CRA 가 자동으로 읽어서,
기존 프로젝트로 나가야 할 배포까지 새 프로젝트를 바라보게 된다. 전환 시점에 복사한다.

## 2. 새로 발급받아야 하는 것

옮겨도 따라오지 않는 것들이다. **이걸 안 바꾸면 이관 후에도 요금이 기존 계정으로 계속 나간다.**

| 항목 | 지금 | 필요한 조치 |
|---|---|---|
| **솔라피(문자)** | 형 계정. `sms-gateway-vm`(34.64.211.220, GCP 프로젝트 `gateway-9eb9b`)이 경유 | 의뢰인 명의로 가입 → API 키·시크릿 발급 → **발신번호 사전등록**(승인에 시간 걸림) → 충전 |
| **SMS 게이트웨이 서버** | 형의 공용 VM (다른 프로젝트의 crawl-server 들과 같은 프로젝트) | (a) 의뢰인 쪽에 새로 세우거나 (b) 게이트웨이를 걷어내고 Functions 에서 솔라피 직접 호출 |
| **카카오 로그인** | 형 명의 앱 (REST 키 `ae8b70…`) | 의뢰인 명의 앱 생성 → REST/네이티브 키, 플랫폼·리다이렉트 URI 등록, 키 해시 등록 |
| **Gemini API 키** | 형 계정 | 의뢰인 명의 키 발급 (AI 견적 기능) |
| **구글 로그인** | 기존 프로젝트에 설정됨 | 타깃 콘솔에서 사용 설정 + 승인된 도메인 추가 |

> 게이트웨이는 형의 다른 프로젝트들과 VM 을 공유하므로 **GCP 프로젝트째 넘기면 안 된다.**
> (b) 안으로 가면 이관 대상에서 서버가 아예 빠지고 의뢰인이 관리할 것도 줄어든다.

## 3. 데이터 이관

스크립트와 옵션은 `scripts/migrate/README.md` 참고.

```bash
# 확인
node scripts/migrate/auth-copy.mjs      --dry-run
node scripts/migrate/firestore-copy.mjs --dry-run
node scripts/migrate/storage-copy.mjs   --dry-run

# 실행
node scripts/migrate/auth-copy.mjs
node scripts/migrate/firestore-copy.mjs
node scripts/migrate/storage-copy.mjs
node scripts/migrate/rewrite-urls.mjs    # DB 에 박힌 옛 프로젝트 URL 치환

# 검증
node scripts/migrate/verify.mjs
```

**규모(2026-08-09 기준):** Firestore 문서 1,515건(서브컬렉션 포함) / Auth 18명(전원 비밀번호 보유) / Storage 97개 77.8MB.

- **UID·문서 ID·파일 경로가 모두 유지된다.** `users/{uid}` 같은 연결이 그대로 살아 있다.
- **비밀번호도 유지된다.** 소스의 SCRYPT 파라미터를 함께 넘겨 import 하므로 기존 회원은 쓰던 비밀번호로 로그인된다.
- 이관 중 소스에 새 데이터가 들어오면 그만큼 빠진다. 사용이 적은 시간대에 하고, 끝난 뒤 한 번 더 돌려 차이분을 채운다(이미 있는 건 건너뛰므로 반복 실행해도 안전).

## 4. 배포

```bash
# 규칙·인덱스
firebase deploy --only firestore:rules,firestore:indexes,storage --project homepro-9202f

# Functions (functions/.env.homepro-9202f 값이 채워져 있어야 함)
firebase deploy --only functions --project homepro-9202f

# 웹
cp .env.client .env.production
npm run build
firebase deploy --only hosting --project homepro-9202f
```

콘솔에서 직접 해야 하는 것 (API 로 안 됨):
- Authentication > 로그인 방법: 이메일/비밀번호, 구글 사용 설정
- Authentication > 승인된 도메인에 서비스 도메인 추가
- IAM: 서비스 계정에 **Service Account Token Creator** — 카카오 커스텀 토큰 발급에 필수. 빠지면 카카오 로그인이 통째로 깨진다

## 5. 앱(안드로이드·iOS)

앱이 배포돼 있으면 `google-services.json` / `GoogleService-Info.plist` 를 새 프로젝트 것으로 교체하고 **재빌드 → 스토어 재심사**가 필요하다. 여기가 가장 오래 걸린다.

그래서 **웹은 즉시 전환되지만 앱은 심사 통과까지 구버전이 옛 프로젝트를 본다.**
→ 심사가 끝나고 사용자 대부분이 새 버전으로 넘어갈 때까지 **기존 프로젝트를 지우면 안 된다.** 한동안 병행 유지한다.
