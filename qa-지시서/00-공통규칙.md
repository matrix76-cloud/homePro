지휘: 카스(메인 터미널). 이 문서 + 카테고리 지시서 1장을 받은 터미널 에이전트는 아래 규칙대로 점검을 수행한다.

## 환경
- 프로젝트: /Users/a1111/Downloads/2026Dev/mainproject/2026Web/homePro
- dev 서버: http://localhost:3002 (이미 떠 있음 — 새로 띄우지 말 것. 죽어 있으면 지휘에게 보고)
- 테스트 로그인: http://localhost:3002/seed-login 에서 계정 버튼 클릭 (접수자=성실한청소부, 홈프로=노련한장인 등)
- 브라우저 자동화: puppeteer 사용. 모듈 로드는 아래 방식(프로젝트에 puppeteer 미설치):
  ```js
  const { createRequire } = await import("module");
  const require = createRequire("/Users/a1111/.npm/_npx/55158e48eb5c59f7/");
  const puppeteer = require("puppeteer");
  const browser = await puppeteer.launch({ executablePath: "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome", headless: "new", args: ["--no-sandbox"] });
  ```
- 뷰포트 390x844(모바일). 관리자 화면은 1280x900.

## 산출물 (자기 폴더에만 쓴다 — 다른 카테고리 폴더 금지)
- 폴더: public/qa/<지시서에 적힌 dir>/
- 스크린샷: 항목 id와 같은 이름 (예: p01.png) — 판정 직후 화면
- 결과 JSON: 지시서에 적힌 파일명 (예: _flow.json). 형식:
  ```json
  [ { "id": "p01", "name": "기능명", "action": "수행 내용", "ok": true, "note": "확인 결과 한 줄", "shot": "p01.png" } ]
  ```
  문제 발견 시 ok: false + note 에 증상. 스샷 필수.
- 점검 끝나면 public/qa/manifest.json 의 자기 카테고리만 수정:
  status "pending"→"done", dir·date 추가, sections: [{ "label": "...", "sub": "...", "file": "_flow.json" }],
  발견 버그는 bugs: [{ "text": "...", "status": "미수정(보고)" 또는 "수정 완료" }]
- 결과 확인: http://localhost:3002/review/qa-board 에서 자기 카테고리 버튼 눌러 표가 뜨는지 확인

## 데이터 규칙
- Firestore 는 시드/테스트 데이터만 만들고, **점검이 끝나면 만든 데이터는 삭제(원상복구)**. 기존 데이터 수정·삭제 금지.
- 문자(SMS) 실발송 항목은 실행하지 말고 note 에 "솔라피 연동 후" 표기.
- 배포(firebase deploy) 금지 — 배포는 지휘가 모아서 한다.

## 코드 수정 규칙 (파일 충돌 방지 — 가장 중요)
- 지시서의 [수정 허용 파일] 목록에 있는 파일만 수정 가능. 그 외 파일의 버그는 **수정하지 말고** 결과 JSON ok:false + manifest bugs 에 "미수정(보고)"로 기록.
- 공용 파일(src/service/*, src/config/*, functions/*, App.js)은 항상 보고만.
- 수정한 경우 커밋하지 말 것 — 지휘가 검수 후 커밋.
