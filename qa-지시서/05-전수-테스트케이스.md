# [테스트 에이전트] 전수 테스트케이스 지시서

지휘: 카스(메인 터미널). qa-지시서/00-공통규칙.md 를 먼저 읽고 이 지시서를 수행한다.
방식은 doum(도우미) 프로젝트에서 확립한 QA 러너 방식이다: 케이스 전수 조사 → 상황별 케이스 작성 → 자동 실행 → 스샷 증빙 → 리뷰 허브 결과표.

## 목표
앱에서 나올 수 있는 테스트 케이스를 전부 조사해 목록화하고, 각 상황(정상/실패/경계)별 케이스를 만든 뒤, 케이스별로 자동 테스트를 돌려 검사 결과를 스크린샷으로 남긴다. 결과는 /review/qa-board 에서 표로 보인다.

아래를 훑어 기능 인벤토리를 만들고, 기능마다 케이스(정상·실패·경계)를 도출한다.

- 카테고리 접수폼: src/config/orderFormConfig.js (25종/종목784)

- 기존 점검 커버리지: public/qa/manifest.json (13카테고리, 7/29 완주) + qa-지시서/01~04

목록 형식: `| TC id | 도메인 | 기능 | 상황(정상/실패/경계) | 절차 요약 | 기대 결과 | 기존 커버(회차) |`

### 심화 관점 (기존 점검과 다른 각도 — 반드시 이 관점들로도 케이스를 도출할 것)
기존 13카테고리는 "기능이 명세대로 도는가"(happy path + 일부 경계) 관점이었다. 이번엔 아래 관점으로 놓친 구멍을 찾는다. 관점마다 최소 5케이스 이상 도출하고, TC 목록의 "상황" 열에 관점 태그를 단다.
1. **권한·접근 통제**: 비로그인/타인/타 역할로 URL 직접 진입 — 남의 오더 상세·남의 채팅방·프로 전용 화면(접수자로)·관리자 페이지(일반 계정)·proOnly 공동중개(일반 회원). 화면 차단뿐 아니라 Firestore 쓰기가 실제로 막히는지.
2. **동시성·경합**: 두 홈프로가 같은 오더 동시 수락, 견적 이중 제출, 비교선정에서 이중 선정, 같은 계정 두 탭에서 상반된 조작(한쪽 취소·한쪽 완료).
3. **상태 전이 매트릭스**: 오더 상태 6종 × 허용되지 않은 전이 시도(완료된 오더 취소, 취소된 오더에 견적, 배정 전 작업완료 등). 화면에 버튼이 없어도 URL/액션 직접 호출로 뚫리는지.
4. **데이터 정합성 교차검증**: 화면 표시값 vs Firestore 원본 대조 — 포인트 잔액=원장 합계, 등급=활동실적 재계산, 오더 카운트/뱃지 수, 채팅 안읽음 수. (시드 포인트는 원장과 무관하다는 기존 함정 주의)
5. **내성·복구**: 흐름 중간 새로고침/뒤로가기/딥링크 재진입(견적 작성 중, 결제·포인트 차감 직후, 온보딩 중간), 로그아웃 후 뒤로가기로 잔여 화면 접근.
6. **입력 악성·극단**: XSS 문자열(`<script>`, `"><img onerror>`)이 채팅·리뷰·오더 설명에 그대로 렌더되는지, 초장문(1만자)·특수문자·RTL 문자, 음수/0/소수점 금액. (경계값 19건과 겹치는 건 "기존 커버" 표기)
7. **회귀(리그레션)**: 7월에 고친 버그들 재발 확인 — 가입 온보딩 튕김, 커뮤니티 익명/좋아요, location 크래시, 취소사유 버그, price/긴급 버그, 중복선정. 각각 재현 절차 그대로 다시 밟는다.
8. **기존 회차 감사**: 7/29 "커버리지 매핑"으로 퉁친 기본 기능점검(카테고리 0) 항목 중 실측 없이 매핑만 된 것을 골라 실제로 3~5건 재실측.

- 목록이 완성되면 일단 보고하고, 지휘/형 확인 후 단계 2로.

## 단계 2 — 러너 작성
- 참고 패턴: scripts/qa-boundary.mjs (이 프로젝트 표준 — puppeteer createRequire 로드, BASE=http://localhost:3002, 결과 push 형식)
- doum 원본 참고: /Users/a1111/Downloads/2026Dev/mainproject/2026Web/doum/scripts/qa_lib.mjs (계정 분리·회차 폴더 규칙)
- 그룹별 러너: scripts/qa-<그룹>.mjs (예: qa-bizprofile.mjs, qa-grade.mjs, qa-brokerage.mjs)
- 테스트 계정: /seed-login 계정(성실한청소부·노련한장인 등). 새 계정 필요하면 시드 규격 준수, 끝나면 삭제.

## 단계 3 — 실행·증빙
- 산출물 폴더: public/qa/20260731-<그룹>/ — 항목 id와 같은 이름의 스샷(예: t01.png) + _flow.json
  ```json
  [ { "id": "t01", "name": "기능명", "action": "수행 내용", "ok": true, "note": "확인 결과 한 줄", "shot": "t01.png" } ]
  ```
- ★함정: public/ 에 파일을 쓰면 dev 서버가 리로드된다 — 러너는 스샷·JSON 을 임시 폴더(예: /tmp/qa-out)에 모았다가 **테스트가 다 끝난 뒤 한 번에 public/qa/ 로 복사**할 것.
- 끝나면 public/qa/manifest.json 에 자기 카테고리 추가/갱신(00-공통규칙 형식), http://localhost:3002/review/qa-board 에서 표 확인.
